Soul Taker — Troubleshooting
01
오디오 중첩 생성 오류
증상
특정 이벤트(몬스터 처치, 아이템 획득 등) 발생 시 효과음이 여러 번 겹쳐 재생되거나 AudioSource 오브젝트가 씬에 중복 생성됐습니다.
원인
Object Pool로 관리되는 오브젝트가 반환될 때 AudioSource의 Play 상태가 초기화되지 않아 재사용 시 기존 클립이 재생 중인 상태로 새 클립이 추가 재생됐습니다. 또한 이벤트 구독이 OnDestroy에서 해제되지 않아 씬 재진입 시 리스너가 중복 등록됐습니다.
해결
ObjectPool의 OnRelease 콜백에서 AudioSource.Stop() 및 clip 초기화를 추가했습니다. 이벤트 구독은 OnEnable/OnDisable 쌍으로 관리해 씬 전환 시 중복 등록을 방지했습니다.
02
몬스터 다른 룸 오추적 버그
증상
플레이어가 다른 룸에 있을 때 NavMesh 몬스터가 벽을 향해 계속 이동하거나 제자리에서 방향을 반복 전환하는 현상이 발생했습니다.
원인
NavMeshAgent.SetDestination이 경로 유효성 검증 없이 즉시 호출됐습니다. 룸 간 NavMesh 경로가 단절되어 있어도 SetDestination 자체는 실행되어 도달 불가능한 목적지를 향해 이동했습니다.
해결
NavMesh.CalculatePath로 경로 유효성을 사전 검증하고, PathStatus == PathComplete인 경우에만 SetDestination을 호출하도록 수정했습니다. 경로가 불완전하면 Wander 상태로 전환합니다.
03
씬 전환 시 장착 아이템 스탯 초기화
증상
로비에서 장비를 장착한 후 던전 씬으로 전환하면 장착 아이템의 추가 스탯(공격력, 방어력 등)이 BaseValue로 초기화됐습니다.
원인
씬 전환 후 PlayerManager의 Awake에서 스탯을 BaseValue로 재초기화하는 로직이 실행됐습니다. 장착 아이템 데이터는 UGS에서 정상 로드됐지만 스탯 재적용 로직이 초기화 이후에 누락되어 있었습니다.
해결
SceneManager.sceneLoaded 이벤트에서 장착 아이템 데이터를 불러와 스탯을 다시 적용하는 초기화 순서를 보장했습니다. Awake → 기본 스탯 설정 → sceneLoaded → 장착 스탯 누적 적용 순으로 정리했습니다.
04
퀘스트 완료 시 보상 아이템 중복 지급
증상
퀘스트 완료 확인 버튼을 클릭할 때마다 보상 아이템이 중복으로 인벤토리에 추가됐습니다.
원인
완료 처리 함수에서 상태 전환 전에 보상 지급 로직이 실행됐고, 버튼 클릭 이벤트가 중복 등록되어 한 번의 클릭에 완료 함수가 여러 번 호출됐습니다.
해결
보상 지급 직전에 완료 상태 플래그를 먼저 설정해 재진입을 방지했습니다. 버튼 이벤트는 onClick.RemoveAllListeners() 후 단일 리스너만 등록하도록 수정했습니다.

Troubleshooting — 문제 해결
01
모바일 세로모드 영웅 인벤토리 UI 깨짐
증상
안드로이드 기기 세로 모드에서 영웅 인벤토리를 열면 UI 요소들이 화면 밖으로 벗어나거나 버튼·텍스트가 겹치는 레이아웃 깨짐이 발생했습니다.
원인
Canvas Scaler의 Reference Resolution이 가로(Landscape) 기준으로 설정되어 있었고, UI 요소들의 앵커가 절대 좌표로 고정되어 있었습니다. 세로 해상도(9:16)에서는 비율이 달라져 모든 요소의 위치가 틀어졌습니다.
해결
Canvas Scaler의 Match 값을 Height 우선(0.8)으로 조정하고, 패널과 버튼의 앵커를 화면 비율 기반 상대 좌표로 변경해 해상도 독립적인 레이아웃을 구성했습니다.
02
인벤토리 갱신 시 성능 저하
증상
인벤토리 화면을 열거나 아이템을 획득할 때 UI 갱신 시 순간적인 프레임 드랍이 발생했습니다. 아이템이 많아질수록 딜레이가 눈에 띄게 증가했습니다.
원인
인벤토리 갱신 시 기존 슬롯 오브젝트를 전부 Destroy 후 새로 Instantiate하는 방식으로 구현되어, 아이템 수가 늘어날수록 GC 부하와 오브젝트 생성 비용이 선형으로 증가했습니다.
해결
인벤토리 슬롯에 Object Pooling을 적용해 오브젝트를 재사용하도록 전환했습니다. 갱신 시 슬롯의 데이터(아이콘, 수량)만 업데이트하고 오브젝트 생성·삭제를 최소화했습니다.

Troubleshooting — 문제 해결
01
CorsConfig 빈 충돌로 CORS 오류 발생
증상
프론트엔드에서 API 호출 시 CORS 오류가 간헐적으로 발생했습니다. Spring Boot 기동 시 expected single matching bean but found 2 예외가 출력되며 서버가 비정상 상태로 뜨는 경우가 있었습니다.
원인
SecurityConfig 내부에서 CORS 설정을 정의하면서, 별도로 작성한 CorsConfig 클래스도 CorsConfigurationSource 빈을 독립적으로 등록해 두 빈이 충돌했습니다.
해결

증상
호스트 화면에서는 캐릭터의 이동·공격 애니메이션이 정상 재생됐지만, 클라이언트 화면에서는 해당 캐릭터가 T-포즈로 고정되거나 애니메이션이 전혀 갱신되지 않았습니다.
원인

해결
애니메이션 상태 변경 시 ServerRpc → ClientRpc 순서로 모든 클라이언트에 파라미터를 브로드캐스트하도록 수정했습니다. RPC 방식이 NetworkAnimator보다 불필요한 동기화를 줄여 더 적합했습니다.

원인

해결
Relay를 포기하고 Steamworks 기반 P2P 구조를 유지하면서, 모든 게임 상태 변경을 ServerRpc / ClientRpc 패턴으로 일원화했습니다. 호스트가 권위(authority)를 갖고 상태를 검증한 뒤 ClientRpc로 브로드캐스트하는 구조로 동기화 문제를 체계적으로 해결했습니다.
